# 1.1.3 交付说明（给客户 / 现场运维）

> 本文件面向**非开发人员**：说明这一版改了什么、有什么已知限制、
> 遇到问题怎么判断。技术细节见 `docs/delivery-ledger.md`。

版本：**1.1.3 (5)**
包：`app-release.apk`（生产签名，可覆盖安装 1.1.2 及更早的**同证书**版本）

---

## 一、这一版修了什么（按影响排序）

### 1. U 盘拷贝可能永久失败（最严重，建议升级）

**现象**：某次拷贝过程中如果断电、或被强制关机，之后**每次插 U 盘都不再拷贝**，
界面上没有任何报错，看起来就像"U 盘没被识别"。

**原因**：拷贝时会在存储里建一个隐藏的备份目录（`.playerN_backup`）。
正常情况下用完会删掉。但上一版有个条件写反了，导致它**永远不会被删除**。
一旦残留，下一次拷贝就准备不了备份，直接失败 —— 而且会一直失败下去。

**现状**：已修复。升级后残留的隐藏目录会被自动清理，**无需手动处理**。

> 如果现场有设备已经出现「插 U 盘不拷贝」且暂时无法升级，
> 应急办法是删除残留的隐藏备份目录（需用文件管理器开启"显示隐藏文件"）：
>
> ```
> /storage/emulated/0/RK3568MediaPlayer/.player1_backup
> /storage/emulated/0/RK3568MediaPlayer/.player2_backup
> /storage/emulated/0/RK3568MediaPlayer/.player3_backup
> /storage/emulated/0/RK3568MediaPlayer/.player4_backup
> ```
>
> 若在设置里改过「存储位置」，则改到对应的媒体目录下（结构相同）。
> 只删 `.playerN_backup`，**不要动 `player1` ~ `player4`**（那是正常缓存）。

### 2. 远控 `hide` 命令

**现象**：上一版这个命令从来没有真正生效过（发送方收到"成功"，但应用没退到后台）。

**现状**：已改为在发送前判断应用是否在前台，不在前台时返回错误而不是谎报成功。

> ⚠️ **但还有一个未确认的问题**：本应用被注册为**桌面（HOME）应用**，
> Android 对桌面应用的「退到后台」操作可能无效。这一版是否真的能退到后台，
> **需要现场验证**（见第四节）。

### 3. U 盘插拔后自动刷新

**现象**：之前拔插 U 盘后，界面可能仍显示旧内容；或者反过来，什么都没变却反复弹"是否覆盖"的确认框。

**现状**：已改为按"U 盘内容的指纹"判断——**内容真的变了才处理**。
- 插入 U 盘 → 自动检测并拷贝
- U 盘内容有变化（比如往里加了文件）→ 自动重新处理
- 内容没变 → 不打扰
- 拔掉 U 盘 → 自动切回本地缓存播放

### 4. 存储空间不足时会自动重试

**现状**：空间不足时不再一直卡住。系统会自动重试（间隔从 5 秒逐步拉长到 60 秒），
**清理出空间后无需任何操作即可自动恢复**。

### 5. 图片裁剪后自动切布局

**现象**：裁剪完 2×2 但界面还是单屏，用户以为裁剪坏了。

**现状**：裁剪完成后自动切到对应布局。若切换失败，提示会明确说
「**未能自动切换布局，请手动选择对应模式**」，不再谎称成功。

### 6. 通知文案跟随应用内语言

**现状**：系统语言是中文、应用内选英文时，通知也会显示英文（此前固定跟系统语言）。

## 二、这一版**没有**改的（避免误解）

| 项 | 说明 |
|---|---|
| **四格画面严格同步** | 「2×2 同画面」模式下四格仍会**逐渐错开**。这是四个独立播放器各自缓冲导致的，时间越久越明显。目前的同步功能默认**关闭**——因为强行对齐会让画面每隔几秒闪一下，比不同步更难看。根治需要改架构，不在本版范围 |
| **设备发热** | 四路播放时 SoC 温度实测约 **85°C**，已进入降频区间。这是硬件/ROM 层面的问题（硬解未能走零拷贝路径），不是应用能解决的。建议 ROM 方排查解码器 HAL |
| AC3 音频 | 设备不支持 AC3 直通，会静音播视频（画面正常）。**建议素材改用 AAC** |

## 三、现场运维需要知道的

### 签名密钥（安全事项，需决策）

生产签名密钥 `app.jks` 曾存在于公开的代码仓库历史中，理论上可被恢复。
**建议轮换密钥并清理仓库历史**。步骤见 `docs/key-rotation-checklist.md`。
未轮换前，这个仓库不宜公开。

### HDMI 硬件按键

应用已经支持用 root 权限写 HDMI 控制节点（su 回退）。
但仍**推荐 ROM 侧直接放开权限**（`chmod 0666` 两个节点），
性能更好、且不依赖设备是否 root。

节点路径：
```
/sys/devices/platform/hdmi-control/hdmi_b2   （切换模式）
/sys/devices/platform/hdmi-control/hdmi_b3   （切换分辨率）
```

### 模式编号记法

设置页按「行×列」命名（如「横屏 2×2」= 2 行 2 列）。
拼接板示意图可能按「列×行」标注。两者图形相同，但**文字描述可能相反**，
需与客户确认以哪个为准。

## 四、验收时需要特别确认的 3 项

这三项**在本版本发布前没有条件在真实设备上验证**，
请在验收时重点检查：

### 1. `hide` 命令是否真的能让应用退到后台

```
1. 确保应用在前台
2. 发送 hide 命令
3. 观察：画面是否切换到了别的界面/桌面
```
若画面毫无变化 → 该功能无效，需改用其他方案。

### 2. 存储空间不足时是否会自动恢复

```
1. 让 U 盘内容大于本机剩余空间
2. 插入 U 盘 → 应提示"存储空间不足"
3. 清理出空间（不用重启应用）
4. 观察：是否自动开始拷贝
```

### 3. U 盘插拔是否正常工作

```
1. 插入 U 盘 → 应自动检测
2. 保持插入 30 秒 → 不应反复弹确认框
3. 拔掉 U 盘 → 应自动切回本地内容
```

## 五、已知限制汇总

| 项 | 状态 |
|---|---|
| 四格严格同步 | 不支持（架构限制） |
| 设备过热降频 | 需 ROM 方排查 |
| AC3 音频 | 不支持（建议改用 AAC） |
| 桌面图标名跟随应用内语言 | 不支持（平台行为，只跟系统语言） |
| 模式 5/6/7 文字记法 | 待客户确认 |
| 状态回传含本地绝对路径 | 现有行为，已文档化；如需脱敏需与接入方约定 |
