# I2C 调试页 — 真机实测（RK3568，2026-10-20）

Debug 包启动即进入本页。

## 页面结论（实测）

| 区块 | 实测结果 |
|---|---|
| ① 总线状态 | **不通 · 从机无应答 (ENODEV)**；探测方式 `sysfs: version（存在但读失败）` |
| ② 驱动节点 | **存在 14 / 14**（含 `version`、`status`、`result`、`cmd_count`、`rx_state`） |
| ② 节点读数 | 全部返回 `ENODEV 从机不应答` |
| ③ 持续写 | 自动启动，1 秒一次；计数持续增长，最近错误 `read failed: ENODEV (No such device)` |

## 这组数据说明了什么

节点齐全 + 权限 0666 + 读取全部 `ENODEV`
= **驱动已绑定，但 I2C 从机没有 ACK**。

`i2cdetect -y 4` 曾显示 `30: UU` —— 注意 `UU` 表示该地址**被驱动占用**，
**不代表总线上有应答**。这是本次排查中最容易误判的一点。

需要硬件侧确认：从机供电、SDA/SCL 上拉、地址跳线、pinmux 是否切到 i2c4。

## 根因深挖（2026-10-20 补充）

### 设备上有两套 I2C 控制器

| 总线 | 设备 | 驱动 | 状态 |
|---|---|---|---|
| **i2c-1** | `1-0038` @ 0x38 | `lt86204`（内核自带） | ✅ 正常：节点可读、有 `i2c_fails`/`current_input` 等自有节点 |
| **i2c-4** | `4-0030` @ 0x30 | `hdmi-matrix-ctl` | ❌ 节点齐全，读取全部 `ENODEV` |

### `i2cdetect` 对照（决定性证据）

```
# i2c-1
30: -- -- -- -- -- -- -- -- UU -- -- -- -- -- --
40: -- -- -- -- 44 -- -- -- -- -- -- -- -- -- --

# i2c-4
30: -- -- -- -- -- -- -- -- -- -- -- -- -- -- --
```

- i2c-1 的 `0x44: 44` 是**真实 ACK**（另一个从机）
- i2c-1 的 `0x38: UU` 与 i2c-4 的 `0x30: UU` 都是「驱动占用」标记

### 结论

**i2c-4 上没有实际应答的从机。** 驱动已绑定、节点已创建、权限 0666，
但每一次读写都在总线上得不到 ACK，因此内核返回 `ENODEV`。

需要硬件侧确认（按可能性排序）：

1. **pinmux**：i2c4 的 SDA/SCL 引脚是否真的切到了 I2C 功能
   ```bash
   cat /sys/kernel/debug/pinctrl/*/pinmux-pins | grep -E "pin 138|pin 139"
   ```
2. **从机供电 / 上拉电阻**：0x30 设备是否上电，SDA/SCL 是否有 4.7k 上拉
3. **地址跳线**：从机实际地址是否为 0x30
4. **设备树**：`i2c@fe5d0000` 是否与实际硬件连线一致

> 这不是 App 侧能修复的问题。App 的调试页已经能把这三类故障分别显示出来
> （ENODEV / EACCES / ENOENT），现场可直接按提示排查。

### 硬件层最终确认（绕过驱动）

```bash
# 用 -f 强制访问已被驱动占用的地址
i2cget -y -f 4 0x30 0x00
# → i2c_read_byte: No such device or address
```

即使绕过 `hdmi-matrix-ctl` 驱动，直接对 0x30 发起一次读，硬件仍然没有 ACK。
**这在软件层面已无法再往下查** —— 问题确定在 I2C 物理层或从机侧。

### 已排除的项

| 项 | 结论 |
|---|---|
| 驱动未加载 | ❌ 已排除：`/sys/bus/i2c/drivers/hdmi-matrix-ctl/4-0030` 存在 |
| 节点未创建 | ❌ 已排除：14 个节点齐全 |
| 权限不足 | ❌ 已排除：权限 0666，且 `EACCES` 与 `ENODEV` 是不同 errno |
| SELinux | ❌ 已排除：当前 Permissive（有 avc denied 但 `permissive=1`，被放行） |
| pinmux 未切 | ❌ 已排除：pin 138/139 = `function i2c4 group i2c4m0-xfer` |
| 总线号错 | ❌ 已排除：DT 为 `i2c@fe5d0000`，pinmux 指向同一节点 |

### 需要在硬件侧排查

1. 0x30 从机是否上电（VDD）
2. SDA/SCL 是否有上拉（通常 4.7k）
3. 从机地址跳线是否为 0x30
4. i2c4 与从机之间的实际连线

> 一旦硬件修好，App 侧无需任何改动 —— 调试页会自动从
> 「不通·从机无应答」变成「通·从机应答」，并开始每秒写 mode。
