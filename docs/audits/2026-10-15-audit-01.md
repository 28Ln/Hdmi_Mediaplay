## 一、当时的核心发现

### 阻断交付（P0，11 项）

最严重的几条（详见 `docs/audit-findings.md` 过程记录）：

| 问题 | 根因要点 |
|---|---|
| 布局切换销毁重建 ExoPlayer | `PlayerCell` 不可见时提前 return，令播放器离开组合树触发 release |
| 客户版 U 盘配置全部失效 | UI 层用 `releaseDefaults()` 覆盖了 `FeatureManager` 已应用 U 盘覆盖的结果 |
| ERROR 状态不可逆 | `togglePlayPause` 对 ERROR 原样保留，无其他出口 |
| 拷贝中断丢全部旧缓存 | 每次进入拷贝先删 backup；异常路径不还原 |
| 路径穿越 | `usbScanFolderName` 可传 `../..` 越出 U 盘 |
| 图片裁剪必 OOM | 全尺寸解码且 `catch (Exception)` 抓不到 `OutOfMemoryError` |

### 当时两个「看起来是 bug 其实是误解」的发现

| 现象 | 真实原因 |
|---|---|
| 应用上看不到布局模式描述 | 设备装的是 7 月旧包；那批代码 9 月才改、从未提交 |
| 鼠标滚轮/拖动不滚动 | 见审计 02 与 `mouse-drag-scroll-fix.md` |

### 被推翻的判断（方法论教训）

- 最初推测滚轮是「定制 ROM 映射为 DPAD 方向键」→ 真机 `getevent` 显示是**真鼠标**（`REL_WHEEL`），推测错误
- 之后用 `adb input swipe` 验证滚动「正常」→ 该方法走触摸源，**测不出鼠标拖动问题**，结论无效
