# App 操作的 I2C 节点清单

> 设备：RK3568，Android 11
> 节点根路径：`/sys/bus/i2c/devices/4-0030/`
> I2C：总线 4，从机地址 0x30

---

## 一、14 个节点总览

| 节点 | 可写 | 取值范围 | 含义 |
|---|---|---|---|
| `mode` | ✅ | 0..7 | 拼接模式 |
| `resolution` | ✅ | 0..2 | 输出分辨率 |
| `mirror` | ✅ | 0..15 | TX 镜像位掩码 |
| `rotate` | ✅ | 0..3 | 旋转角度档位 |
| `hfusion` | ✅ | 0..255 | 水平融合带（**写入会写 MCU flash**） |
| `vfusion` | ✅ | 0..255 | 垂直融合带（**写入会写 MCU flash**） |
| `mute` | ✅ | 0..1 | 音频静音 |
| `power_state` | ✅ | 0..1 | 电源（0=待机，1=开机） |
| `key` | ✅ | 任意 | 兼容旧按键语义（新代码不依赖） |
| `version` | ❌ | — | 协议版本，`2` = 在线 |
| `status` | ❌ | — | 状态位：bit0 BUSY / bit1 POWER / bit6 ERR / bit7 OVF |
| `result` | ❌ | — | 上一条命令结果，`0` = OK |
| `cmd_count` | ❌ | — | 已执行命令计数（模 256） |
| `rx_state` | ❌ | — | bit n=1 表示 RX n 有稳定输入 |

**共 8 个可写、5 个只读、1 个兼容用。**

---

## 二、各节点的取值含义

### `mode`（拼接模式）

| 值 | 含义 |
|---|---|
| 0 | 1×1（单屏） |
| 1 | 1×2（横屏两路左右并列） |
| 2 | 2×1（两路上下分屏） |
| 3 | 1×3（三路左右并列） |
| 4 | 3×1（三路上下分布） |
| 5 | 2×2（四路方阵） |
| 6 | 1×4 |
| 7 | 4×1 |

### `resolution`

| 值 | 分辨率 |
|---|---|
| 0 | 720p |
| 1 | 1080p |
| 2 | 2160p30 |

### `rotate`

| 值 | 角度 |
|---|---|
| 0 | 0° |
| 1 | 90° |
| 2 | 180° |
| 3 | 270° |

### `mirror`（位掩码）

- 值域 `0..15`，每 bit 对应一个 TX 通道是否镜像
- **仅当 `mode` 达到阈值时才允许写**：
  - TX3 板：`mode >= 3`
  - TX4 板（默认）：`mode >= 5`
- ⚠️ **写 `mode` 会清空 `mirror`** —— 固件行为，App 会在写 mode 后强制重写 mirror

### `status`（位域）

| bit | 含义 |
|---|---|
| 0 | BUSY（忙） |
| 1 | POWER（已上电） |
| 6 | ERR（错误） |
| 7 | OVF（溢出） |

## 三、App 界面操作 → 实际写的节点

### 设置页「布局模式」

| 界面选择 | 写 `mode` | 写 `mirror` | 说明 |
|---|---|---|---|
| 模式 1（横屏 1×2） | `1` | 是（若当前 mode 允许） | |
| 模式 2（横屏 1×3） | `3` | 是（若允许） | |
| 模式 3（竖屏 1×2） | **不写** | **不写** | 纯软件布局 |
| 模式 4（竖屏 1×3） | **不写** | **不写** | 纯软件布局 |
| 模式 5（横屏 2×1） | `2` | 是（若允许） | 注意是 **2**，不是 5 |
| 模式 6（横屏 3×1） | `4` | 是（若允许） | |
| 模式 7（横屏 2×2） | `5` | 是（若允许） | |
| 1×4 | `6` | 是（若允许） | |
| 4×1 | `7` | 是（若允许） | |
| 软件模式（2×2 同画面） | **不写** | **不写** | 纯软件布局 |
| SINGLE / PIP | **不写** | **不写** | 纯软件布局 |

> **纯软件布局共 6 种**：模式 3、模式 4、2×2 同画面、SINGLE、PIP、以及竖屏模式。
> 选择这些布局时，App **完全不碰 I2C**。

### 设置页「HDMI 拼接板（I2C）」区块

| 控件 | 写的节点 | 备注 |
|---|---|---|
| 电源 ON/OFF | `power_state`（0/1） | 状态未知时禁用 |
| 静音 ON/OFF | `mute`（0/1） | 状态未知时禁用 |
| 720p / 1080p / 2160p30 | `resolution`（0/1/2） | 直接指定值，不受状态影响 |
| 融合带滑杆（水平） | `hfusion` | **松开才写**，且写 flash |
| 融合带滑杆（垂直） | `vfusion` | 同上 |
| 旋转 | `rotate` | |

⚠️ **融合带（`hfusion` / `vfusion`）每次成功写入都会写 MCU flash**，
因此 App 做了 **300ms 防抖**，且只在**松开滑杆**时提交。

### 底部栏

| 按钮 | 操作 |
|---|---|
| 切换模式 | 循环 `mode`（纯软件布局不参与） |
| 切换分辨率 | 在 720p → 1080p → 2160p30 间循环 |
| 设置 | 进入设置页 |

### 远程控制命令

| 命令 | 写的节点 |
|---|---|
| `set_layout` + `layout_mode` | `mode` + `mirror`（同设置页映射） |
| `set_volume` | **不写 I2C**（仅应用内音量） |
| `set_mute` | `mute` |
| `set_loop_mode` | **不写 I2C** |
| `play` / `pause` / `stop` | **不写 I2C** |
| `get_status` | **只读**（读 `version`/`status`/`result`/`cmd_count`/`rx_state`） |
| `show` / `hide` | **不写 I2C** |

## 四、App 读节点的时机

| 场景 | 读什么 | 频率 |
|---|---|---|
| App 启动 | `version`（`ensureOnline` 轮询） | 250ms 一次，最长 20 秒 |
| 下发前预检 | 读当前 `mode` 判断是否需要写 | 每次布局操作 |
| 写后校验 | 回读刚写的节点 | 每次写 |
| 设置页打开 | `version` + `probe()` + `readApplied()` | 进页面时一次，之后每 10 秒 |
| **I2C 调试页** | 全部 14 个节点 | **每 5 秒一轮** |
| **I2C 调试页写循环** | 读 `mode` 再写回 | **每秒 1 次** |

> ⚠️ **I2C 调试页是唯一会持续产生总线上流量的页面**（Debug 包启动首页）。
> 正常播放页面**完全不产生 I2C 流量**（实测：60 秒 0 条）。

## 五、写入的执行顺序（重要）

### 布局下发（`applyLayout`）

```
1. 读 mode            ← 预检
2. 写 mode            ← 固件会清空 mirror
3. 读 mode            ← 校验写是否成功
4. 写 mirror          ← 即使回读为 0 也强制写（因为第 2 步清空了）
5. 读 mirror          ← 校验
```

**为什么 mirror 必须强制重写**：写 `mode` 时固件会清空 `mirror`，
如果只比较「回读值 == 目标值」就会跳过写入，导致镜像设置丢失。

### 融合带提交（`commitFusion`）

```
1. 检查距上次写入是否 >= 300ms（防抖，保护 flash）
2. 写 hfusion
3. 写 vfusion
4. 若期间有新值暂存，合并后再写一次
```

## 六、错误处理与重试

| errno | 含义 | App 行为 |
|---|---|---|
| `EACCES` (13) | 权限不足 | 先试 `su` 提权，仍失败则报错 |
| `EPERM` (1) | 从机待机 | 尝试写 `power_state=1` 唤醒一次后重试 |
| `EIO` (5) | 总线错误 | 重试 1 次 |
| `ENOENT` (2) | 节点不存在（驱动未加载） | **不重试**，UI 隐藏控制入口 |
| `ENODEV` (19) | 节点在但从机无应答 | **不重试**，标记「拼接板无应答」 |
| `EINVAL` / `ERANGE` | 值非法 | 不重试（写前已校验，出现即为 bug） |

## 七、纯命令行操作示例

```bash
BASE=/sys/bus/i2c/devices/4-0030

# 读全部节点
for n in mode resolution mirror rotate hfusion vfusion mute power_state \
         key version status result cmd_count rx_state; do
  printf "%-12s = " "$n"; cat $BASE/$n 2>&1
done

# 切换到 2×2 模式（mode=5）
echo 5 > $BASE/mode

# 设置 1080p
echo 1 > $BASE/resolution

# 开机
echo 1 > $BASE/power_state

# 取消静音
echo 0 > $BASE/mute
```

⚠️ **不要用 `i2cdetect` 排查**：该工具会扫描 0..0x7F 全部地址，
扫到无应答地址时可能卡住并占用适配器锁，导致后续所有访问 `EBUSY`。

## 八、当前现场注意事项

### I2C 故障规律（2026-10-21 实测）

| 重启方式 | 结果 |
|---|---|
| **断电重启**（拔电源） | I2C 可用约 **203 秒**，之后永久失效 |
| **`reboot`**（不断外设电） | **从头就是坏的**，`ipd: 0x00` |

**只有断电重启能恢复。** 驱动重绑、设备重建、`i2cget` 直连全部无效。

### 排查时建议

1. **不要长时间停留在 I2C 调试页** —— 该页每秒写 `mode`，是唯一的持续流量来源
2. **需要观察时用「进入播放」离开调试页** —— 播放页零 I2C 流量
3. **不要用 `i2cdetect`** —— 会卡住适配器锁
